# 账号凭证守护（智能运维 → 凭证守护）

面向 OpenAI OAuth 账号的令牌健康巡检与自愈能力，作为「智能运维」下的子页面提供：

- 页面路径：`/admin/token-guard`
- 接口前缀：`/api/v1/admin/account-ops/token-guard/*`
- 默认关闭：代码内置参考测活/重登服务 https://session.ameng2027.xyz（含对应请求头与模型 gpt-6-astra），
  启用前确认参数即可；也可以改成任意兼容该协议的第三方服务。

## 工作方式

1. **定时巡检**：在所选分组内覆盖 `active` 和 `error` 状态的 OpenAI OAuth 账号，排除手动禁用、已删除和影子账号。按配置间隔用账号当前的 `access_token` 调用「测活接口」，结果分为 `正常`、`令牌失效`、`临时异常`；每轮上限和按上次探测时间轮转仍生效。
2. **令牌失效自愈**：命中失效、达到配置的连续失效阈值且开启自动重登时，用配置的 `邮箱 + 密码 + 2FA 密钥` 调「重登接口」换新凭据，随后写回凭据（保留 `model_mapping` 等字段）→ 清错误态 → 按配置恢复调度 → 失效服务端 token 缓存。业务请求已记录 `Token revoked (401):`、`Unauthorized (401):`，或账号测试记录的 `Authentication failed (401):` JSON 正文含明确令牌失效码（如 `token_revoked`）时，直接按令牌失效处理，不再依赖测活接口确认；普通测活 HTTP 401/429、超时和连接失败仍视为临时异常，不单独触发重登。
3. **错误态自愈**：探活正常但账号仍为 `error` 状态时，自动清除错误态并恢复调度。
4. **可观测**：账号最近一次探活结果与巡检/修复日志全部落库，页面展示并支持单账号手动重登。

自动重登每个账号独立使用最长 25 分钟的预算，不占用探测阶段的剩余超时；取消巡检或停止服务仍会取消登录请求。重登失败保留账号错误状态与脱敏失败原因，下一轮选中该账号时再次尝试。重登服务自身持续返回 429、登录凭据错误或上游风控仍可能导致失败，需要根据守护日志处理；不会因一次重登失败自动清除错误态。

## 配置项

| 字段 | 说明 |
| --- | --- |
| 启用守护 | 关闭后不做任何巡检与修复 |
| 守护分组 | 留空表示全部 OpenAI OAuth 账号；页面通过下拉菜单支持多选分组 |
| 巡检间隔 / 超时 / 并发 / 每轮上限 | 站点测活较慢时用「每轮上限」控制单轮规模，未覆盖账号下一轮优先 |
| 测活接口 / 测活模型 | 默认指向参考服务 session.ameng2027.xyz 与 gpt-6-astra，可替换 | `POST {probe_endpoint}`，请求体 `{"access_token": "...", "model": "..."}`，按 NDJSON 返回 `{"type":"result","payload":{...}}` |
| 测活 / 重登 额外请求头 | 每行一个 `Header-Name: value`；值里可用 `{{uuid}}` 生成每次请求唯一的随机串；接口协议要求由配置提供，代码不内置任何第三方标识 |
| 自动重登 / 重登接口 / 重登凭据 | 页面每行使用 `账号----密码----2FA`（兼容旧逗号格式）；接口请求体为 `{"action":"start","email":"...","auth_mode":"password_2fa","password":"...","mfa_secret":"..."}`，返回 `credential` 对象 |
| 修复后恢复调度 | 修复成功后重新打开账号调度 |
| Bark Key / 推送开关 | 可选，修复成功或失败时推送通知 |

## 数据表

- `account_token_guard_states`：每个账号最新巡检状态（探活结果、延迟、连续失效次数、最近修复）。
- `account_token_guard_events`：巡检与修复日志，保留最近 14 天。

## 安全说明

- 巡检只读取账号已有的 `access_token`，不会主动修改账号凭据。
- 仅在「令牌失效且开启自动重登」时写回新凭据，并保留账号既有配置字段。
- 重登凭据保存在管理员设置中，请只在自建环境填写；对外共享数据库前建议先清空该字段。

## 首次 2FA 登录导入

在「账号管理 → 添加账号」选择 **OpenAI → 2FA**，填写分组、代理等账号设置后点击「下一步」。账号名称可留空，默认使用邮箱；填写时作为名称前缀。在登录凭据框中每行输入 `邮箱----密码----2FA密钥`，点击「登录并导入」。兼容逗号分隔，最多 100 条，不接受缺字段或重复邮箱；2FA 填长期密钥，而非六位验证码。

- 复用本页**已保存**的重登接口与额外请求头，包括 `{{uuid}}`。无需已有账号，也无需开启巡检或自动重登。
- 逐条启动后台登录任务，页面轮询结果；登录成功后使用 Session 导入器生成 OpenAI OAuth 账号，保留表单的分组、代理、并发及模型等设置。
- 已有身份跳过，不覆盖其凭据和配置。新增的 Session 导入参数 `skip_existing: true` 控制此行为，未传时保留原接口语义。
- 单条失败不阻断后续记录；“继续未完成的记录”跳过已完成项。登录已成功但导入失败时，在当前弹窗中重试会复用令牌，不再登录。停止按钮取消当前登录并停止后续记录；若账号导入已经发出，等待该次导入结果后停止。
- 2FA 登录成功后，密码与 2FA 密钥按规范化邮箱自动保存或更新到凭证守护；保存失败不会返回登录成功。其他守护配置保持原值，不会自动开启巡检或重登。密码和 2FA 不写入账号令牌导入结果或审计正文；建议保留默认邮箱名称以匹配现有重登规则。
- 自动保存仅适用于支持该功能的版本完成的新 2FA 登录，不会补回历史导入、令牌导入或其他方式创建账号时缺失的密码和 2FA。已有账号提示“缺少重登凭据”时，需在凭证守护中补录，或再次通过 2FA 登录完成保存；账号导入阶段跳过已有身份不影响此前已成功保存的重登资料。
- 登录任务最多 32 个，单次登录最长 25 分钟，任务及返回令牌在内存中最多保留 30 分钟；导入完成或取消后主动清理。进程重启后未完成任务失效，刷新/关闭弹窗不提供持久恢复。
