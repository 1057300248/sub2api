# Cline raw Chat and terminal-event boundary follow-up

Reviewed base: `1f34a290f94ec5a154f34f47ce8a7dadd7d367c6` on `codex/sub2-v297-cline-fixes-20261003`.

Raw Chat now removes noncanonical case-fold aliases of the complete Chat DTO field set before reading/mapping core fields or sending upstream. Canonical fields remain authoritative; an alias alone is not promoted. All duplicate decoded top-level names, including escaped names and duplicate vendor keys, fail with 400. This avoids first-key/last-key disagreement without guessing which duplicate the caller intended. Nested vendor values are copied as RawMessage; numbers, false/zero and genuinely nested names are retained. This is not recursive validation of arbitrary vendor schemas. Other providers are unchanged.

The SSE guard already stopped reading the source at a complete [DONE] event in the reviewed base. The actual remaining race was the outer lifetime/read-error adapter replacing that logical EOF with a late caller deadline. The guard now reports verified completion only after the complete terminal frame has been delivered from its pending buffer. The lifetime then retains EOF, and the error adapter does not manufacture a failure from a nil/EOF scanner result after that terminal state. Genuine parser failures, incomplete delimiters, errors before [DONE], usage-only and finish_reason-only streams remain failures. Body Close still owns cancellation and is idempotent; no timeout is extended.

Validation includes four required race-enabled unit tests and 24 required real Sub2API handler/PostgreSQL 18.6 cases: six raw Chat JSON/SSE alias cases across independent Cline and official-host legacy OpenAI/DeepSeek accounts; fifteen duplicate-key rejection cases; and three protocol cases whose source stays open after [DONE] while the actual caller deadline expires inside Forward after terminal output. The upstream uses the real case-insensitive encoding/json decoder, but authentication identity and upstream transport are synthetic. Rejections must make no upstream call or debit; successes must debit once, preserve ledger dedup and release the body and concurrency slots. Existing 42 handler cases and prior failure/cancellation regressions remain intact.

Read the exact candidate SHA's CI results before claiming these cases passed. This change does not validate real NewAPI-to-Cline routing, final provider selection, historical 20-second first-token failures, current production overrides, a restored production schema or database rollback. No production configuration, credentials, accounts, main/stable, release tags or deployment are changed.
